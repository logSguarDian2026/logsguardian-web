Criteria met under normal and attack load, not under volume

Memory criterion not met

The protocol sets at most 150 MB of added memory (≈143 MiB). The measured increase is more than double that in every scenario. The library repository revised its internal gate to 300 MB, and the measured increases exceed that value too.

CPU criterion not met

The protocol allows up to 15% relative CPU increase under normal and attack load. Both scenarios exceed it by a wide margin. The whole container was measured, so the cost cannot be attributed to any component.

Earlier builds, Docker and Postgres

Earlier builds and environments gave absolute p95 overhead between about 3 ms and 14 ms in Docker and Postgres, with relative increases of +70% to +266%. They used builds other than pair B or C, so they are not comparable to the table above.

Component inference, complementary

During a grace-window instrumentation pass (250 sampled requests), the mean session.run() time was 0.026 ms for Random Forest and 0.978 ms for Isolation Forest. Under sustained load for 60 s, the Isolation Forest mean per call was between 2.99 and 3.22 ms across ten consecutive segments.

Build note. Latency, memory, and CPU were measured with pair B, the first build of rf_v11 / if_v10, not with the 0.1.1 package (pair C). The thesis reports this difference explicitly.

Of the 40 attacks CRS (PL1) let through, logSguarDian caught 37 after they passed the WAF. Attribution uses the response signature (X-Powered-By: Express appears only on application-layer blocks). Three payloads passed both layers, and none is a working exploit against the target app.

This corpus overlaps training

Under normalized equality, all 200 cmdi payloads match a row in the training, validation, or test partitions (63 match literally). Seven of 113 xss payloads match, and no sqli or path_traversal payload does. Excluding those matches, Config 2 coverage was 98.7% sqli, 97.2% xss, and 98.5% path_traversal. Because of this overlap, the cmdi result is not evidence of generalization. The cleaner evidence is the Round 5 run below.

Zero-protection baseline

With no WAF and no middleware, 6 of 6 tested attack vectors compromised the app: SQLi authentication bypass, SQLi UNION exfiltration, stored XSS in two fields, path traversal on attachments, and command injection on the admin ping utility, which ran whoami and returned root.

Harness note, 0.1.1 package

The 0.1.1 package was run by the co-author in the vulnerable-app repository. With the original harness, it gives the same results as pair C (path_traversal 190/200, cmdi 192/200). A corrected harness that sends payloads unencoded gives path_traversal 200/200 and cmdi 185/200, with one timeout. The 200/200 result is optimistic because it was measured on the corpus that exposed the defects. The thesis annex reports both runs.

Scanner check, OWASP ZAP

ZAP 2.17.0 found one reflected XSS in the bio field of POST /profile. That one case was blocked in configurations 2, 3a, and 3b. A single payload does not establish compliance with an 80% criterion for xss.

User-Agent dependence

Why the User-Agent matters

Feature importance (SHAP)

Using TreeExplainer on the Random Forest, ua_length ranks first for benign (mean |SHAP| 0.0866) and for sqli (0.0734). ua_present ranks second for benign.

Training distribution

Only 0.4% of benign training rows have a User-Agent longer than 40 characters. Between 33.3% (xss) and 97.7% (path_traversal) of attack rows do.

Source: SHAP global importance table and the User-Agent length distribution table, thesis results chapter, interpretability section.

Generalization

Leave one source out

Excluding one source from training changes the result a lot for some sources. Removing modsec_learn, payloads_csv, or xss_dataset raises the benign false positive rate to 76.0%, 27.0%, and 94.5%.

Excluding synthetic_nav left its benign rows nearly undetected, which led to adding synthetic_nav_ecommerce to the corpus. The thesis does not report a verified metric for that before-and-after; the leave-one-source-out result file does not record the model used.

Dataset

383,202 labeled rows from 17 sources

Split: 268,240 training, 57,481 validation, 57,481 test. Nine sources are public (seven audited, plus SecLists and PayloadsAllTheThings), seven are generators written for this project, and one is curated telemetry from the MLOps pipeline.

Not all traffic is real. The telemetry source (119 rows) comes from a simulated pipeline run, not from live traffic. Two sources have unclear licenses from their publishers (XSS_dataset and command injection), so raw data is not redistributed. AIT-LDSv2 was excluded because its labels describe attacker roles, not payload types.

Reading these numbers

What these figures do and do not show

The thesis reports these metrics as separation within the corpus. It does not claim that they predict performance on unseen traffic. The full list of limits is on the Limitations page.
