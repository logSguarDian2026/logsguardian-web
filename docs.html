Architecture, config, and the CLI

How to install and configure logSguarDian, the pipeline that decides every verdict, and the CLI reference. The package version is .

Quick start

Three steps to a running middleware

npm install logsguardian
npx logsguardian config init

This writes logsguardian.config.js in the current directory. Mount the middleware after your body parsers, such as express.urlencoded and express.json, and after any multer instance if your app accepts file uploads.

const express = require('express');
const { logsguardian } = require('logsguardian');
const config = require('./logsguardian.config.js');

const app = express();
app.use(express.urlencoded({ extended: true }));
app.use(express.json());
app.use(logsguardian(config));

Every request past that point is inspected. Attacks get an HTTP 403, and everything else is forwarded unchanged. Requires Node.js 20 or later, and Express 4 (4.18 or later) or Express 5.

Start in mode: 'monitor' to see what would be blocked before you turn on enforcement.

Native binary: onnxruntime-node requires glibc. Alpine images use musl, so the native binary does not load there. Use a glibc-based image such as node:20-slim.

Architecture

Request in, verdict out

Feature extraction runs once per request and produces a 76-feature vector. Random Forest uses 69 of them and Isolation Forest uses 63. Random Forest excludes seven features: status_code, which is unknown when the middleware intercepts the request; the five temporal features, which need state the extractor does not keep; and non_json_quote_count. Isolation Forest also drops six features that have zero or near-zero variance on benign traffic.

Decision policy

rf_classes   = ['benign', 'cmdi', 'path_traversal', 'sqli', 'xss']
RF_THRESHOLD = 0.35
IF_THRESHOLD = 0.004205941820353609   // if_v10, frozen in model metadata

predicted_class = rf_classes[argmax(rf_probs)]
confidence      = max(rf_probs)
is_attack       = predicted_class != 'benign'
is_anomaly      = if_score < IF_THRESHOLD

if is_attack AND confidence >= RF_THRESHOLD:  verdict = 'block'
else if is_anomaly:                            verdict = 'pass_anomaly'
else:                                           verdict = 'pass'

The middleware rebuilds the query string with URLSearchParams before extracting features. The thesis reports that this changes some feature values for the same request, and that its test metrics do not include that effect.

Configuration

Options in logsguardian.config.js

module.exports = {
  mode: 'block',               // 'block' (403 on attacks) or 'monitor' (log only)
  threshold: 0.35,             // RF confidence at or above which a request is blocked
  model: 'hybrid',             // 'rf', 'if', or 'hybrid'
  timeoutMs: 50,               // fail-open timeout for the RF worker
  dbPath: './logsguardian.db', // SQLite event log and webhook registry
  webhookUrl: undefined,       // optional static webhook, called on block or anomaly
};

Event log (SQLite)

Each detection row stores: timestamp, method, path, query_string, user_agent, client_ip, verdict, predicted_class, confidence, if_score, is_anomaly, webhook_sent, elapsed_ms.

Webhooks send the detection event as JSON, with a 3-second timeout. A failed delivery never changes the response. Because Isolation Forest answers asynchronously, a row written as pass can later be updated to pass_anomaly.
